This PR does exactly that and nothing more — a thin RepoDecisionsPage wrapper that decodes the :repo route param and renders the existing DecisionTimeline/DecisionGraph components, plus links from RepoRow to reach them, with no backend changes and no new dependencies.

I read RepoDecisionsPage.jsx, RepoRow.jsx, and the existing DecisionTimeline.jsx/DecisionGraph.jsx directly to check correctness rather than trusting the description: decodeURIComponent in RepoDecisionsPage correctly round-trips the encodeURIComponent used in RepoRow's new links (needed since repo names contain '/'), the view prop dispatch matches the two new App.jsx routes, and the new routes sit inside the same setup-gated AppShell route group as /library and /settings. The new/updated tests (App.test.jsx, RepoRow.test.jsx, and the MemoryRouter wrapping added to LibraryPage.test.jsx now that RepoRow renders router Links) assert getDecisions call shapes that match what DecisionTimeline/DecisionGraph actually call. PR #193: **approve** — No sensitive-path hold applies: this PR touches only frontend/src/library/FileTree.jsx and its test file, not backend/auth/, backend/config_store.py, .github/workflows/*, any migration, or backend/retrieval/search.py.

On the merits: the change matches the product decision recorded in ROADMAP.md for #145 exactly — "two calls (caret vs. name-text click target); frontend-only pre-fill, backend path filter deferred to its own issue." The diff splits each directory row into a caret button (expand/collapse only) and a separate name button (navigates to `/` with a pre-filled, path-scoped question via router state), and file rows get the same name-click behavior. No backend/`POST /query` change was made, consistent with the stated scope.

Verified independently rather than taking the PR body's claims at face value: `FileTree` is not imported/mounted anywhere else in the frontend, so `AskPage` legitimately doesn't need to consume `state.prefillQuestion` yet — that's accurately described as staged infra, not an unfinished feature. The `prefillQuestion` state shape also lines up with `AskPage.jsx`'s existing `prefill` state naming, so it should wire in cleanly whenever `FileTree` is mounted.

Tests were updated to match the new two-button structure (aria-label based lookups for the caret, name-based lookups for the click-through targets), added coverage for both directory and file navigation calls to `useNavigate`, and added an explicit assertion that toggling the caret does not trigger navigation. This is a small, self-contained, in-scope frontend change with no evidence of scope creep.
