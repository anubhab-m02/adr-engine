PR #177: **request_changes** — No sensitive path is touched (only ROADMAP.md and backend/requirements.txt), so this isn't a denylist hold — it's a scope objection.

This PR is titled and described as a pure Dependabot version bump (python-dotenv 1.0.1 → 1.2.2), and the actual dependency change (backend/requirements.txt) is a correct, minimal one-line bump that I'd otherwise approve on its own.

However, the diff also contains a large, unrelated rewrite of ROADMAP.md (~85 of the 91 added lines): new "Product decisions" resolving #138/#129/#145, a "Ready to promote" section for #172/#173, a Dependabot-alerts process note, and a rewritten Evaluation section about the eval harness/#108/#171. Per this repo's own convention ("One daily-task issue per PR. Don't expand scope mid-issue."), a dependency-bump PR should not carry an unrelated, substantive roadmap/product-decision rewrite. Please drop the ROADMAP.md changes from this branch (they appear to already be on main and are just causing the conflict) and let this PR contain only the dotenv bump, or reopen the roadmap content through its own PR if it isn't actually landed yet.
