# Review report — 2026-11-25

## PRs reviewed

PR #323: **request_changes** — This is a scope objection, not a sensitive-path hold. The diff touches none of the denylisted paths (backend/auth/, backend/config_store.py, .github/workflows/*, migrations, backend/retrieval/search.py).

Issue #302 lists two files: SourceCard.jsx and SourceCard.test.jsx. It caps the diff at about 80 lines. CLAUDE.md says "One daily-task issue per PR. Don't expand scope mid-issue."

The PR goes past that in two ways:
1. It rewrites `frontend/src/lib/useBookmarks.js`, which the issue does not list. The change swaps `useState` for a module-level `useSyncExternalStore` store. It adds listeners, a snapshot cache, a `storage` event subscription and an in-memory fallback. `BookmarksList.jsx` also consumes this hook, so its behavior changes too. That was merged one day earlier in #322.
2. The diff is 105 additions and 20 deletions, over the ~80-line budget.

Two further points:
- The shared-store fix may be a real bug fix, because two cards each had their own state. It should go in its own issue and PR, with its own tests in `useBookmarks.test.jsx`. The PR changes the hook without adding tests there.
- The new wrapper `<div className={`relative ${widthClassName}`}>` moves the width class onto the wrapper. Please confirm the inner `<a>` still lays out correctly. The link's id, href and aria-label look unchanged, so citations appear intact.

Please split the hook refactor into a separate issue and PR. Keep this PR to the SourceCard button and its test.

PR #328: **approve** — No sensitive paths touched. The diff only changes frontend/src/ask/SourceCard.jsx and SourceCard.test.jsx, so the denylist hold doesn't apply. The change matches issue #307:
- The Copy link button is a sibling of the `<a>`, not nested in it.
- It writes `unit.url` through `navigator.clipboard.writeText`.
- "Copied" shows in a `role="status"` element and clears after about 2s, with the timer cleaned up on unmount.
- A missing or rejecting clipboard is a silent no-op.
- The link's href, aria-label and `id=source-{id}` are unchanged, so citation traceability is preserved.

Tests cover the success path, an unavailable clipboard, and the button sitting outside the link. The diff is about 80 lines, within the ~100-line budget.

Two minor notes, neither blocking:
- The new wrapper `<div>` and the inner `<a>` both get `widthClassName`. This is harmless, because the widths are equal and the anchor is a block.
- The JSX inside the new wrapper isn't re-indented, which could trip a formatter or lint check. CI should catch that.

PR #329: **approve** — No sensitive-path hold: the diff touches only `frontend/src/lib/useAnnotations.js` and its test file. It doesn't touch `backend/auth/`, `backend/config_store.py`, `.github/workflows/*`, migrations, or `backend/retrieval/search.py`.

The change matches issue #308 and stays in scope. It creates exactly the two files the issue lists. The hook exposes `get`, `set` and `remove` over `{url, note, updatedAt}` entries under a single localStorage key. An empty or whitespace note removes the entry. Missing or corrupt JSON falls back to empty state, and malformed entries are filtered out. There is no backend change. The tests cover set/get/remove, replacing a note, empty-note removal, remount persistence, corrupt JSON and malformed entries. Nothing here touches the synthesis or citation pipeline.

I didn't run `npm test`, lint or build. I also didn't read `useReadingPreferences.js`, so I can't confirm the pattern match the issue asks for. I didn't count diff lines against the issue's ~100-line limit. The hook is about 64 lines.

Minor note, not blocking: `persist` runs inside the `setEntries` updater. React StrictMode may call updaters twice. The write is idempotent, so this is harmless.
