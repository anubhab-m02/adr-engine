One non-blocking nit: the JSX inside the new wrapper div is not re-indented.

PR #341: **approve** — No sensitive-path hold applies. The diff touches only frontend/src/components/CommandPalette.jsx and its test file. It doesn't touch backend/auth/, backend/config_store.py, .github/workflows/*, migrations, or backend/retrieval/search.py.

The change matches issue #318. It touches only the two files the issue names. It adds a filterable "Keyboard shortcuts" action that opens a labelled dialog with role="dialog" and aria-modal. The dialog lists only shortcuts that exist today. Escape closes it and focus returns to the prior element. The diff is 116 additions, under the 150-line target.

Tests cover each acceptance point, and the existing palette tests were updated for the fifth action. I did not run them. The change doesn't touch ingestion, extraction, citations, or synthesis, so those CLAUDE.md constraints don't apply.

Minor nit, not blocking: the added fragment wrapper in the JSX is left unindented.

PR #342: **approve** — No sensitive-path hold applies. The diff only touches frontend/src/shell/AppShell.jsx and AppShell.test.jsx, which are not on the denylist.

The change matches issue #319. A fixed `type="button"` "Exit focus mode" button renders only while focus mode is on. It sits after the skip link in DOM order, so keyboard users can reach it. It calls `toggleFocusMode`. The diff is about 28 lines, under the 60-line target, and nothing falls outside the issue's scope.

The new test covers each acceptance point: the button is absent when focus mode is off, it appears when focus mode is on, and clicking it restores TopNav and removes it. The existing palette test is scoped to the dialog with `within(...)` because the button name is now duplicated. That is a reasonable adjustment, and the test still checks the same behavior.

The change doesn't touch ingestion, extraction, citations or the backend, so the CLAUDE.md conventions on those don't come into play. I read the code and diff but did not run the test suite.

PR #343: **approve** — No sensitive paths touched. The diff only changes frontend/src/lib/useBookmarks.js and its test file. The denylist (backend/auth/, config_store.py, workflows, migrations, retrieval/search.py) is not involved.

The change matches issue #325. It replaces per-instance useState with a module-level store read through useSyncExternalStore, plus a `storage` event listener, which is the fix the issue proposed. toggle re-reads the current snapshot before writing, so two instances can no longer overwrite each other's bookmarks. The public API (toggle, isBookmarked, list) is unchanged. Corrupt-JSON tolerance is kept: parse() returns [] on bad JSON, and getSnapshot falls back to the in-memory list if storage throws. The snapshot is cached against the raw string, so its identity is stable and useSyncExternalStore won't loop.

Both acceptance tests were added: two instances toggling different URLs with both stored and visible in both, and a live cross-instance update without remount. The diff is small and stays in scope. I didn't run the test suite, so I haven't confirmed the existing useBookmarks and BookmarksList tests still pass. I judged this from reading the diff.
