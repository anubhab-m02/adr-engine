# Review report — 2026-11-26

## PRs reviewed

PR #323: **request_changes** — This is a scope hold, not a sensitive-path hold. The diff touches none of the denylisted paths (backend/auth/, backend/config_store.py, .github/workflows/*, migrations, backend/retrieval/search.py).

Issue #302 lists only `SourceCard.jsx` and `SourceCard.test.jsx`, caps the diff at about 80 lines, and CLAUDE.md says "don't expand scope mid-issue". The PR goes past that in three ways:
1. It rewrites `frontend/src/lib/useBookmarks.js`, which is outside the issue's file list. The rewrite replaces `useState` with a module-level `useSyncExternalStore` store, adds a memory-override fallback, and adds a `storage` event listener. That changes the behavior of an existing hook that `BookmarksList.jsx` also uses.
2. The diff is 105 additions and 20 deletions, over the roughly 80-line limit.
3. `useBookmarks.test.jsx` was not updated for the new shared-store semantics. Module-level state (`lastRaw`, `lastList`, `memoryOverride`) can leak between tests.

SourceCard also gets a new wrapper `<div className="relative ${widthClassName}">` around the citation link. The anchor presumably still carries `widthClassName` too, so widths or layout may be applied twice, and this is not covered by the tests. The new `Saved`/`Save` label has no extra context for screen readers beyond `aria-pressed`, and the `aria-label` doesn't change with state. That is minor.

The shared-state problem the rewrite fixes is real: two cards could overwrite each other's bookmarks. The fix belongs in its own issue and PR for the hook. Split it out, then keep this PR to a small SourceCard change on top of it. The citation link's id, href and label are preserved, which is good.

PR #330: **approve** — No sensitive-path hold applies. The diff touches only frontend/src/ask/SourceCard.jsx and SourceCard.test.jsx. It doesn't touch backend/auth/, backend/config_store.py, .github/workflows/*, migrations, or backend/retrieval/search.py.

The change matches issue #309 and stays in scope. It adds a Note button with aria-expanded that reveals a textarea named "Your note". The textarea is a sibling of the card link and not inside it. Its initial value comes from useAnnotations().get(unit.url), and it saves on blur through set(). Clearing the text removes the note, because the existing hook's set() deletes the entry when the note is empty. The link and citation URL are unchanged, so citations stay traceable. Notes are stored locally only and are not sent anywhere.

The tests cover the expand behavior and accessible name, persistence across re-render, and removal after clearing. The diff is 74 added lines, under the ~120-line limit. I did not run npm test, lint or build, so those acceptance criteria are unconfirmed.

PR #331: **approve** — No sensitive-path hold: the diff touches none of backend/auth/, backend/config_store.py, .github/workflows/*, migrations, or backend/retrieval/search.py. It adds only two frontend files, useRecentQuestions.js and its test, which are exactly the files issue #315 names. Scope matches the issue: the hook returns { questions, add, clear }, uses the localStorage key recentQuestions, orders newest first, caps at 10, and dedupes on trimmed text. It ignores blank input, and missing, corrupt or non-array stored JSON yields []. The tests cover every listed acceptance case. The diff is 135 lines, under the 150-line target. There are no backend changes and no citation or extraction pipeline impact. Storage failures are handled gracefully. A small nit, not blocking: persist() runs inside the setState updater, which is impure under StrictMode, but it is idempotent, so it is harmless.
