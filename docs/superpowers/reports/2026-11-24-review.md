# Review report — 2026-11-24

## PRs reviewed

PR #323: **request_changes** — This is not a sensitive-path hold. The diff touches none of the denylisted paths. It is a correctness objection.

The change stays within issue #302's scope. The citation anchor keeps its id, href and aria-label, and the diff is small.

The problem is data loss when several cards are on screen. Each SourceCard calls `useBookmarks()`, and the hook keeps its own `useState(readStored)` snapshot, read once when the card mounts. `toggle` computes the next list from that instance's snapshot and overwrites the whole `localStorage['bookmarks']` entry with it. SourceCardList and SourcesView render many cards at once, so this breaks as follows:
1. Cards A and B both mount with an empty list.
2. The user clicks Save on A, and storage becomes `[A]`.
3. The user clicks Save on B. B's snapshot is still empty, so storage becomes `[B]` and A's bookmark is lost.

The UI also goes out of sync with storage. A shows "Saved" until it remounts, even though storage no longer holds it.

The new test renders only one card, so it can't catch this. Please fix it by either re-reading storage inside the `toggle` updater, or sharing state across hook instances (a module-level store or `useSyncExternalStore`, plus a `storage` event listener). Add a test that renders two cards, toggles both, and checks that both persist.

The `useBookmarks` hook is outside this PR's diff, so the fix can go in either place. Whichever you choose, keep the change tied to this issue.
